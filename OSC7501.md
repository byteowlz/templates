# OSC 7501 — Program Status Protocol (byteowlz adoption note)

Byteowlz convention: long-running programs report their status to the terminal with the
[OSC 7501 Program Status Protocol](https://mitchellh.com/writing/program-status-osc7501)
(Mitchell Hashimoto). Replaces heuristic screen-scraping (e.g. matching spinner characters) and
per-tool socket APIs.

## When to use it

Emit OSC 7501 from anything long-running that a human or an orchestrator (herdr, oqto) watches
from outside: agents (pi sessions, subagents, oqto runner agents), model servers (ds4, SGLang,
vLLM, llama.cpp launch scripts), transcription/rendering/sync/backup jobs, build/deploy steps.

## The protocol

```
ESC ] 7501 ; state=<state>[:key=value ...] ESC \
```

- `state` (required): `idle` | `working` (optional `progress=0-100`) | `done` | `blocked`
  (add `kind=permission|question|auth` and `msg=<base64 line>`) | `error`
- optional keys: `app=<machine-readable name>`, `msg=<base64 human line>`, hierarchical ids for
  task trees (`parent:child`), `clear` to remove records.
- Safe everywhere: well-behaved terminals ignore unknown OSCs; the pty works over SSH, in
  containers, and in VMs with no extra bridging.

## Shell helper (POSIX sh)

```sh
status() { printf '\033]7501;state=%s:msg=%s\033\\' "$1" "$(printf '%s' "$2" | base64 | tr -d '\n')"; }

status working "Syncing photos"
rsync -a ~/Photos backup:/photos && status done "Photos synced" || status error "rsync failed"
```

## Relation to AGENT_CTX

Complementary channels, opposite directions:

- **AGENT_CTX (see `byteowlz/schemas/agent-context-env`)** = identity/context, INBOUND, injected
  by the layers (platform -> multiplexer -> harness -> host): who am I (platform/session/agent/
  model/correlation). Used for linking + search (trx, mmry, hstry, skdlr).
- **OSC 7501** = status, OUTBOUND, emitted by the program: what am I doing right now
  (idle/working/blocked/done/error) for humans and orchestrators.

Non-terminal agents (background/server/voice agents; anything without a pty) should report the
SAME status vocabulary over a non-pty transport, attributed with their AGENT_CTX identity bag
(agent id, platform session id, request/correlation id). Proposed: one status schema, two
transports.

## Attribution note

When emitting status, include `app` (stable program name) and, where available, reuse the
AGENT_CTX ids (agent id / request id) in the hierarchical id so orchestrators can correlate the
status with AGENT_CTX-attributed records.
