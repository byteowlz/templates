# Program status and AGENT_CTX

Byteowlz convention (accepted 2026-10-07): adopt
[OSC 7501](https://www.superlogical.com/rex/docs/build/program-status) in apps
where terminal-visible status is useful. This note summarizes revision 0.2;
the external specification is authoritative.

## Where it makes sense

- Terminal-attached agent harnesses: working, blocked for input, turn done, error.
- Long-running foreground builds/deploys, transcription, ingestion, renders,
  sync jobs and model loading: lifecycle state and known progress.
- Multiplexers and terminal product surfaces: consume explicit reports when
  available; retain legacy detection as fallback for non-emitting programs.

Do not emit into redirected logs/JSON, spam per-token/heartbeat updates, or force
OSC into headless apps. Async job submission is not job completion. Servers can
report startup working then ready/idle; health/readiness remains a service API concern.

## Wire essentials

```
ESC ] 7501 ; state=working:id=build/test:app=cargo:progress=40 ESC \
```

- States: `idle`, `working`, `done`, `blocked`, `error`; `clear` removes a record
  and descendants. `kind=permission|question|auth` applies to blocked only.
- Fields use `:`; hierarchical ids use **`/`**, not `:`. IDs are terminal-local
  paths, not arbitrary global agent/session ids. Absent id addresses the root.
- Every report replaces its whole record; repeat relevant app/title/msg keys.
- `msg` and `title` are base64 UTF-8 plain text. Reject decoded controls, invalid
  base64 and oversize reports according to the spec. Rate-limit notifications.
- Working/blocked expire on process exit or shell prompt; done/error survive.
  No heartbeat resends. Cancellation reports idle.
- SSH transports terminal bytes, but multiplexers can intercept OSCs. Test real
  tmux/herdr/SSH/container paths and feature detection; don't assume passthrough.
- A blocked permission indicator is not an approval or capability grant.

Use a bounded, tested emitter/parser following the spec rather than copying an
unbounded shell helper into every app. Prefer the host's existing terminal I/O.

## Relation to AGENT_CTX and headless apps

AGENT_CTX is injected **runtime metadata**, not AGENTS.md or repo memory. Its
standalone owner is `wismut/agent-ctx` on Forgejo:
`ssh://git@forgejo/wismut/agent-ctx.git` (local `../agent-ctx`). Read `PROPOSAL.md`,
`docs/status.md` and `docs/migration.md` there. Existing v2 schema URLs remain valid;
v3 includes the approved optional `AGENT_CTX_EXEC_ENV` environment/profile label.
Update our owned readers/writers together with tests; preserve old persisted records,
without a prolonged dual-write rollout for hypothetical external consumers.

- Runner/platform/multiplexer/harness/host inject facts they know.
- Context identifies the session/agent/request/execution binding; it is not live
  status. Missing facts mean unknown, never local/trusted/idle. Working statuses belong
  in lifecycle events, not mutable AGENT_CTX_STATUS/PROGRESS env variables.
- Non-terminal apps report compatible status meanings through their existing
  structured runner/harness activity channel, with selected context attribution.
  Do not rewrite env continuously or commit heartbeat files to git.
- Receivers bind source identity from the supervised process/authenticated channel;
  env values and terminal bytes cannot assert authority. Do not transmit whole
  env bags, credentials, or private text. Existing collector ownership remains intact.

## New-app proof checklist

Test state transitions, cancellation/crash cleanup, subtree clear, full replacement,
malicious/oversize text, redirected output, mux propagation and notification dedupe.
Headless reporting also needs reconnection/expiry and old-execution-binding replay
checks. Enabling a schema or declaring support is not integration proof.
